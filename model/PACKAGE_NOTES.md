# Gazebo xLights package

12-sided gazebo (side 50.6", post-centre circumradius 97.75"), posts 71" tall, wall top 72.5", ring base 89".
**1525 pixels, 1 pixel = 3 channels (RGB), 4575 channels total.** No pixels on braces or on the top joists (they duplicate the 72" rails). Pixels face inward.

## Files
- `gazebo.xmodel` - xLights custom model (3D: width 189, height 90, depth 188; 1 grid cell = 1 inch). Node n = pixel n in the CSV.
- `gazebo_pixels.csv` - index, start channel, port, member, member number, position in member (geometric), x/y/z in inches.
- `*.fseq` - 20 fps, 50 ms/step, v2 uncompressed, 4575 channels/step, channel 1 = pixel 1 red.

## Node order = wiring order (4-line plan (v4), Kulp K4 4 ports)
See `docs/physical_layout_v4.md`. Posts 1-12 CCW from the entrance; face f = post f to post f+1 (entrance = face 12, posts 12-1).
"up" = post base > top or rafter wall end > ring; "dn" = the reverse. "72" f2 (3>2)" = 72" rail on face 2 run from post 3 to post 2.
Regenerate with `GAZEBO_LAYOUT=v3` for the previous Layout F v3 order.

Member counts: posts 420, rafters 480, 36" rails 275, 72" rails 300, ring 50.

## Caveats
- Generated by script; **not opened in xLights or FPP**. Classic `<custommodel parm1/parm2/Depth CustomModel=...>` layout.
- Custom models cannot store "faces inward"; use the CSV positions. Coordinates rounded to 1" cells.
- Ring: 50 px equally spaced (pitch ~1.7"), not 2". Rails: 25 px per face at 2" (48" span).
